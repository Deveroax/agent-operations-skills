# Synthetic worked example: four components

**All components, records, observations and outcomes in this example are fictional and synthetic.** These are teaching fixtures, not real tool receipts, executed tests, legal findings or actual release approvals.

## Synthetic evidence register

- **E1 — creation and test record:** a fictional maintainer's dated creation note says they wrote RowSort from scratch without imported source; a separate fictional owner confirmation authorizes a clean MIT edition. A fictional saved test record reports sorting and duplicate-row tests passed on synthetic rows. These statements exist only inside this example.
- **E2 — upstream notice:** a fictional checkout named TraceView includes a notice crediting the fictional North Orchard maintainers under MIT. The only local changes are a diagnostic patch; there is no evidence of local authorship of the underlying tool.
- **E3 — workflow record:** a fictional team confirms local authorship and permission to prepare a sanitized review edition of its handoff checklist. The private version contains client names, machine paths and runtime excerpts. It is useful for repeatable handoffs, but no extracted edition has been tested or approved for publication.
- **E4 — unresolved snippet:** a parser fragment in a scratch file lacks a creation record, source notice or identified import origin. One bounded exact-name lookup provides no additional evidence. This does not prove infringement, public-domain status or original authorship.

## Extraction and release decision — synthetic

Prepare RowSort alone in a clean directory, not the private workspace. Its synthetic evidence supports candidacy, not a claim that this document executed it. Retain the upstream tool's notice; a local patch does not convert the whole tool into original work. Prepare only a review draft of the checklist after removing the three sensitive categories identified in E3, including any occurrences in paths and diagnostics. Keep the parser out rather than borrowing RowSort's permission for it.

A scan with no findings would only describe the scanned bytes and patterns. Manually review the extracted artifacts, their notices, filenames and fixtures; preserve any failures. The proposed independent actions remain bounded and permissioned. No component in this fictional example has actually been published, and no customer validation or revenue is evidenced.
